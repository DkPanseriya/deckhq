## 1. The 100× thesis in five lines

1. **Publish today, then never let a human be the release step again.** Tag → CI → npm with provenance.
2. **The viral primitive is a number, not a picture.** `npx deckhq doctor` prints a personal, surprising, pasteable fact in ten seconds. Lead every launch with it. The floor is the second click.
3. **Live where the user already lives.** Claude Code status line, Claude Code plugin, VS Code, a floating mini-floor, a terminal list. The browser tab is one surface among six, not the product.
4. **The one keystroke that justifies everything: approve from here.** Answer a permission prompt from the panel, and later from the phone. It is the daily dopamine, the reason to keep the daemon up, and the paid tier.
5. **Sell storage and reach, never the floor.** Relay ($9) and Teams ($18/seat) on a bring-your-own-storage design that keeps the zero-egress promise literal even for paying customers.

The floor earns the screenshot. The deck does the job. **The number does the spreading.**

### 1.1 Standing rules for every agent on this plan

These carry over from the 2 September brief unchanged in substance, and they outrank everything
else in this document.

1. **The invariant is inviolable.** `docs/01-PRODUCT.md` §2. No observed event may clear a
   user-owned state. There are named `INVARIANT:` tests; a change that needs them relaxed is the
   wrong change.
2. **The free core stays MIT, local and egress-free.** No analytics, no update checks, no CDN
   assets, no telemetry, ever, including after we charge. Paid features are services you opt into,
   never gates on the local UI.
3. **No runtime dependencies in the core.** Dev dependencies are fine. A runtime dependency needs
   the orchestrator's written approval and a changelog line.
4. **Capture beats features.** If the choice is between a feature and every session appearing,
   capture wins.
5. **Every feature is scored against §1.2.** If it only increases dwell time, it does not ship.
6. **Never score the human.** Agents can have names, faces, traits and histories. The user never
   has a streak, a level, a badge or a guilt message.
7. **Cost is an estimate, never a bill.** Labelled as such everywhere it appears.
8. **All runtime-format parsing stays inside its adapter.** Nothing outside `src/adapters/` reads a
   transcript or shells out to a runtime CLI.
9. **Every deviation from a plan document gets a numbered entry in `docs/DEVIATIONS.md`** with its
   reason and its measurement.
10. **Nothing ships without a screenshot.** The worst bugs in the project's history were invisible
    to the unit suite and obvious in one PNG.
11. **A claim in anyone's documentation is a hypothesis until measured on a machine.** C1 in
    `01-AUDIT.md` §6 is the case that made this a rule.

### 1.2 The fatal risk, named

The floor is beautiful, and beauty in this category has a specific failure mode: it increases
watching. If DeckHQ becomes a thing people leave open and stare at, it is Pixel Agents with better
rendering and it gets the same "observational theater" review.

Countermeasure, binding on every package: **the product's job is to let you stop watching.** It
reaches you when the tab is closed. When you come back, it discharges one item in one keystroke
with everything you need already on screen. It sends a daily card so not looking is safe. Every
feature is scored against one question: *does this reduce the time the user must spend looking at
DeckHQ per unit of agent output?* Features that only increase dwell time are rejected, however
pretty. §14's added refusal is this test made structural.

### 1.3 The one-sentence pitch, for reuse everywhere

> **DeckHQ** — every AI coding session on your machine, on one office floor. It sees the ones your
> terminal forgot, and it remembers what's waiting on you even after you've read it. `npx deckhq`.
> Local, private, MIT.

### B1 — The number is the wedge, not the floor

v1 leads Wave 1 with the hero GIF and the capture-proof image. Both need someone to look at a
picture. The tool that owns this exact audience, ccusage, reached 18k stars on one mechanic:
`npx ccusage` prints a table people paste into threads. No image, no design, no argument.

DeckHQ already has the command. `deckhq doctor` prints:

```
  transcripts     69 sessions across 17 projects
  running now     7   (claude code's own agent view reports 7)
  on the floor    69  ← 62 sessions have already finished; the agent view no longer lists them
  waiting on you  0   (4 waiting, all still running)
```

Every developer who runs it gets a personal, true, slightly alarming fact about their own machine,
and it is text — it works on Hacker News, Reddit, Discord and Slack where images are weak. The
launch headline becomes **"Run `npx deckhq doctor`. Post your fourth line."** The floor is what
they see when they run the command without `doctor`.

Changes: `doctor` gets a `--share` flag that prints a fenced, pasteable block with the pitch line
and nothing private (no paths, no project names). The honesty tests in §74 already govern its
wording and keep governing it.

### B4 — Approve from here is P1, not P2

v1 puts the permission-approval spike (WP-19) in P2 and gates the paid tier on it. It is the
feature that decides the pitch, the price, and whether the product is a monitor or a work
surface. It moves to the first day of P1, runs in parallel with the review card, and its result
determines the README's second sentence.

The route is now known (§3.0.2): a `PermissionRequest` hook of type `http` pointed at the daemon,
installed with the same tagged, consented, port-aware discipline as the existing hooks. The
daemon holds the request open, renders it in the panel with **Allow / Deny / Allow for this
session**, and answers the hook. Silence falls through to the terminal prompt, so a closed
DeckHQ never blocks a session. Codex has the same hook, so the spike covers both runtimes. The
`--permission-prompt-tool` path stays as the fallback for headless sessions DeckHQ spawns itself.
**Nothing about this goes in a README or a tweet until it has run end to end on the reference
machine.**

### B5 — Sell early, gate nothing

v1 sells nothing until month 4. The Wrapped moment in December is the second-best selling moment
of the year and the plan must have something to sell before it. Changes:

- **Month 1:** GitHub Sponsors tiers live, and a **Supporter pack** — floor themes, night shift,
  custom avatars, a rate-card editor — as a signed asset pack outside the MIT core. $29. Gates
  nothing that captures, queues or acts. It is a price probe with dignity.
- **Month 3, not 4–6:** Relay alpha. The spec in `03-BUSINESS-MODEL.md` §3 stands: outbound
  WebSocket only, end-to-end encrypted, self-hostable, off until signed in.
- **Teams is designed in from the ledger onward**, not bolted on at month 6: every ledger entry
  carries a machine id and a project id from day one, so a team floor is a merge, not a migration.
- **Bring-your-own-storage Teams.** The enterprise objection to any agent-monitoring tool is
  "where does the data go". Answer: nowhere of ours. A team floor can be assembled from signed
  ledgers each machine writes to *the customer's* bucket (S3, R2, a shared drive). DeckHQ sells
  the software that merges and renders them, and never holds a byte. This is the product that
  survives a procurement review, it is consistent with the zero-egress promise, and it is the tier
  that funds companies.

### B6 — The floor is generated from the people on it, not from the repositories on disk

The owner's observation on 3 September, confirmed on the live floor: one project has someone at
a desk, and the working floor is ten large empty cells with a plate each. The cause is in
`public/render/plan.js`: `buildProjectRoom(p, p.sessionCount)` sizes desks by **session count**
(benched included), idle projects become "collapsed" rooms that still bid for area, and the
row-squarifier then stretches every cell to tile the band. The floor is built from the disk's
opinion of the team, not from the team.

**The rule that replaces it:** the plan is a function of two numbers — *active projects* (at
least one agent at a desk, hand up, or waiting) and *active agents* — and nothing else decides
partitions or desk counts.

- **Rooms exist only for active projects.** One active project gets the whole working floor as
  one room. Two get a split. Bands and partitions are computed from the active room count, so
  there is never a cell with nobody in it.
- **Desks equal agents at desks,** minimum one table. A project with 20 sessions and 1 working
  agent has one small table, not three benches.
- **Idle projects are a directory, not rooms.** A single compact strip (one line per project:
  name, session count, last activity, click to open the panel or start an agent) along one edge.
  It takes the space of a room plate, not a room.
- **Benched agents live in the lounge, and the lounge is sized by how many are drawn.** Agents
  benched longer than a configurable window (default 7 days) are not drawn; the lounge door
  carries "39 went home"; any activity brings them back. `ackState` is untouched — this is a
  display filter and the `INVARIANT:` tests must pass unchanged.
- **People never shrink below legibility.** With rooms sized to their occupants, the character
  scale floor in `05` §6.2 (16 px body, 11 px label) is reachable at fit on every population.
- **Re-plan on population change, animated.** A room appears when its first agent sits down and
  folds into the directory when its last agent leaves; walls slide, they do not pop.

This is WP-50. It supersedes `05` §6.1 and §6.3 and absorbs WP-40, and it is the single largest
change to what a stranger sees in the first five seconds. It also removes the empty-machine
problem's ugliest form: a machine with history but nothing running shows a directory and an
empty office, which is honest, instead of a building of vacant rooms.

### B7 — Subagents are people too

Claude Code spawns subagents (the Task tool) and they write their own transcript files. Today
they are either invisible or indistinguishable. Rendering them as juniors who sit beside their
parent, appear when spawned and leave when they finish, is (a) true, (b) the most charming thing
the floor could do, and (c) a capture claim nobody else can make. Capture beats features. WP-41.

### B8 — A terminal surface for people who will never open a browser

`deckhq ls` (and `deckhq waiting`) print the deck as a table, oldest first, with the same actions
by id: `deckhq ack MK1.1`, `deckhq bench MK1.1`. Same daemon, same state file, raw ANSI, no
dependency. It triples the addressable audience — the terminal purist who alt-tabs between tmux
panes is exactly the person with the most lost sessions — and it makes DeckHQ scriptable, which is
how it ends up in other people's dotfiles and blog posts. WP-42.

### 3.5 Munder Difflin: what to take, what to leave, how to stand beside it

Assessed 3 September from its repository, site, blog, HN and Reddit threads.

**What it is.** A desktop orchestrator: you talk to a manager agent, it routes work to worker
agents it launched itself, and you watch them on a pixel floor. Exact state comes from a hook
shim it injects with `--settings` into every agent it spawns; hookless runtimes fall back to
PTY output activity; transcripts on disk are read only to reconcile token cost. Fixed Tiled map,
sixteen seats, overflow wanders in from the door.

**What it proves.** The office metaphor sells: 6.2k stars in three months from a floor plus a
sitcom joke. $20/month is an accepted price in this exact audience. HN will give 311 points to a
floor. And the criticism that stuck — *theater*, agents spawning unbidden, a GOD agent burning
tokens, opt-out telemetry, Windows broken until v0.4.4 — is the criticism v1's thesis was written
to avoid.

**What DeckHQ takes** (each is a mechanism, not a vibe):

| Mechanism | Where it lands |
|---|---|
| **Thought bubble = current tool + action text**, from `PreToolUse`/`PostToolUse`. "What is it doing" readable from across the room. DeckHQ installs neither hook today. | WP-52 |
| **Station per tool class**: file ops at the shelf, shell at the CRT, web at the portal. The object is the verb, which DeckHQ already believes for project furniture. | WP-52, as a state icon first; furniture later if the goldens allow |
| **Hook shim via `--settings`** for sessions DeckHQ itself spawns: exact lifecycle without touching the user's global settings file. | WP-19 / WP-37 fallback path |
| **Cheer only after ≥ 60 s busy**, and an idle "director" that any real state change cancels instantly. | `04` §2, WP-15 |
| **"Your draft" as a visible state**: an unsent reply in the composer is shown on the floor as the agent's queue being held by you. | WP-08 |
| **Ask-Me cascade**: a blocked question shows what else is waiting on the answer. | WP-19 panel, when subagents exist (WP-41) |
| **8-bit SFX off by default.** They learned it; we keep sounds to three and low. | `05` §8, unchanged |
| **`munderdifflin://hire` share links and an agent gallery** as a viral loop. DeckHQ's equivalent is text: `doctor --share`. Keep ours. | WP-44 |

**What DeckHQ does not take:** spawning as the price of visibility; a manager agent; Electron;
a native module; a fixed map; telemetry of any kind; the sitcom.

**How to stand beside it.** Never compare in public (`02` §7). The line, when asked: *"Munder
Difflin runs your agents. DeckHQ finds the ones you already ran, wherever you started them, and
remembers what they still need from you."* Their users are the most likely early DeckHQ users,
because they are the people who already believe agents belong on a floor, and DeckHQ shows them
the sessions their orchestrator cannot. The dynamic floor (WP-50) matters more because of them:
"per-project rooms that appear when work starts" is a visible difference from sixteen fixed
seats in every screenshot.

**Risk added to `02` §6:** Munder Difflin adds transcript discovery. It already tail-reads
transcripts for cost; reading them for state is a step, not a leap. The answer is the same as
for the first party: the invariant, breadth of capture, presence without a tab, and speed.

## 7. Dopamine, engagement, gamification

The rule from `04` §1 is binding and unchanged: **the agents are the characters; the human is the
manager, and the manager is never scored.** No streaks, no XP, no badges, no guilt. The evidence
is in `04` §5 and it has not changed.

| Moment | Reward | Frequency | Package |
|---|---|---|---|
| An agent walks into your office | Door sound, floor shadow, badge counts up, status line ticks, mini-floor pulses | Few/hour | WP-15, WP-38, WP-39 |

**Attachment.** Agents get stable faces and first names on first sight (WP-20). Add **rarity**
to WP-20: appearance is a deterministic hash of the session id, and a small set of traits —
a hat, glasses, a jacket, a rare hair colour — sit on tiers (common, uncommon, rare 5%, legendary
1%). The Claude Buddy evidence (§3.0) is that deterministic rarity is what made people screenshot
and share; it costs nothing, it is on the *agent*, and it changes no state. State colour stays on
the torso and the icon above the head, so legibility is untouched. Add **team
records**, which are records of the team's work and never a score on the human: *longest wait
ever* (and whether it has fallen), *busiest day*, *the room that never slept*, *most turns in a
week*. They live in the hover card and in Wrapped. A falling "longest wait" is the most
satisfying number in the product and it is computed from the ledger, not from the human.

**Subagents as juniors** (WP-41) is the strongest attachment mechanic available: the user watches
a senior spawn three juniors, they sit down beside it, and they leave when done. It is true, it is
the runtime's own behaviour, and nobody else draws it.

**Variable reward, kept small.** The lounge already has idle games. Add a rare event or two — a
trick shot, an arcade high score — as flavour, never as a mechanic with a counter.

### WP-54 · The Windows console launch is quoted for `cmd.exe` · `AB` · 0.5d · P0 · landed 3 Sep

Opened during WP-47's review and shipped the same day. Opening a session in a console goes through
`start`, which is an internal `cmd.exe` command, so `cmd.exe` re-parses the whole command line
after it — and Node's Windows quoting wraps a value only when it contains a space, a tab or a
quote, leaving `&`, `|`, `^`, `<` and `>` bare as syntax. Measured on Windows 11: an argument of
`x&y` reached the launched program as `x`, and the session id arrives in a request body. DeckHQ
builds that command line itself now, every value double-quoted, handed over with
`windowsVerbatimArguments`, with `"` and `%` refused rather than escaped; the working directory is
named with `start /d` instead of inherited through two processes. One definition of the rule, in
`src/core/cmdline.mjs`, shared with the `code.cmd` launch WP-47 had already worked out.
**Accepted when:** the defect and the fix are both launched for real, from a working directory
containing a space and an `&`. Done. `docs/DEVIATIONS.md` §98.

### WP-56 · `doctor` names the managed-settings hook kill switches · `AB` · 0.5d · P1 · after WP-19 build

From §97.4's decisions. Two managed-settings keys — `allowedHttpHookUrls` and
`allowManagedHooksOnly` — can switch DeckHQ's `http` hooks off over its head, and **neither is
detected today**. On a managed machine they look exactly like a hook that is installed and never
