Studio

Come with an idea, leave with an office. Studio is an opt-in mode, per project: a plan, a roster and a six-column board that live in your repository, and — eventually — one real coding session per role, found by the same scan as everything else.

Three of the eleven steps exist. The store, the consent and the planner are built. Hire is not: no worktree, no role session, no board tab. Enabling a project creates a directory and a record, and that is all enabling does. Everything on this page marked planned is design, not product.

The loop

Eleven steps, and the whole design is that ten of them reuse something the floor already does. The full version is docs/07-STUDIO-DESIGN.md.

Step What happens Status
Idea One paragraph and a project directory, through the new-project picker. built
Grill A real claude planner session interviews you in the ordinary panel composer. There is no separate Studio chat, because there is no separate anything. built
Blueprint blueprint.md — goal, non-goals, constraints, milestones with their acceptance criteria — written by the planner with its own tools. built
Roster roster.json: the roles, each with a purpose, a prompt, tools, a budget. built
Hire One session per role, in its own git worktree, with its own brief file. planned
Board Six columns as a tab beside the floor, on the deck’s semantic-table rule. planned
Work Reuses everything — the six states, the permission card, the review card, the queue strip, the ledger — and adds nothing, which is the point. planned
Handover A session writes a handover file; the transcript watcher picks it up. planned
Review The handover raises the ordinary review card, with its diff, plus Accept and Bounce. planned
Track Cost and time from the same ledger deckhq stats reads. planned
Drift control A periodic planner pass over blueprint, board and handovers, raising flags as review cards, with a budget stop. planned

What exists today

The store, and the consent

Studio is off everywhere and does nothing until you enable it for a directory. 

deckhq studio enable  ./my-project          # print every path it would write, change nothing
deckhq studio enable  ./my-project --yes    # write one file, and record the grant
deckhq studio disable ./my-project --yes    # take back only what DeckHQ wrote

enable --yes writes exactly one file — <project>/.deckhq/studio/README.md, carrying a marker on its first line — and records the path and the grant. Everything else in that directory, when it arrives, is yours: the blueprint, the roster, the board, your coding rules, the briefs and the handovers. It is not gitignored, because a plan is something a team should be able to commit.

disable --yes deletes only files that still carry the marker and names everything it left alone. A path that would resolve outside .deckhq/studio/ — by .., by being absolute, or through a symlink — is refused with the offending path rather than quietly clamped back inside. Consent is per project and is never inferred from another.

Grill: the interview that writes the plan

Once a project is enabled, ⌘K → Studio: plan this project starts a planner. It is a real claude session in that directory with an interview brief as its first prompt, so it walks onto the floor on the next scan, takes a desk, and you answer it in the ordinary panel composer.

It asks, in turn, for the goal, the non-goals, the constraints, the milestones with their acceptance criteria, and the roles you need. Then it writes blueprint.md, roster.json and board.json and says written.

DeckHQ writes none of them. The planner writes them, as ordinary files, with its own tools. DeckHQ reads them back and checks them, and one that does not check out is reported with its name, its line and the reason — and left exactly as it was written.

The brief itself is yours too: edit it and DeckHQ will never overwrite it; a regeneration is written beside it and yours is what runs. Claude Code only for now — another runtime is refused by name rather than handed a brief nobody has run it against.

The rule the board runs on

A card’s column is yours.

No session ending, no test passing, no file appearing and no budget being spent moves a card. They flag it; you move it. It is the same rule the queue runs on, and it is the reason both are worth having.
