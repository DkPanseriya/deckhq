Hooks and privacy

Everything DeckHQ knows, it read off your own disk. Everything it keeps, it wrote to your own disk. Nothing goes anywhere else, and the last line of deckhq doctor reports the egress it found.

No network egress, ever

  • The daemon binds 127.0.0.1 and nothing else. There is no --host flag and there never will be one. It is not reachable from your network, which is why it needs no password. It also refuses cross-site requests, so a page in another tab cannot drive it.
  • No analytics, no telemetry, no update check, no crash reporting. There is no setting to turn off, because there is nothing to turn off.
  • No fonts or scripts from a CDN — in the product, and on this site. The only sockets are the loopback listener and the runtime processes DeckHQ starts on your behalf.
  • Your conversation content never leaves the machine, and is rendered as text, never as HTML. There is no innerHTML in the client at all.
  • No accounts, no billing, no licence checks. MIT, zero runtime dependencies — you can read the whole thing in an afternoon, and there is nothing underneath it to read.

What it reads from your disk

Path What is read
~/.claude/projects/**/*.jsonl Claude Code transcripts, in bounded chunks: the head for the title, the tail for recent state and token usage. Transcripts on a busy machine reach tens of megabytes, so DeckHQ never reads a whole one.
claude agents --json Which sessions are alive right now.
~/.codex/sessions/** Codex rollout files, when Codex is installed.
~/.claude/settings.json Only if you opt into hooks, and only the block DeckHQ wrote.

What it writes

Path What is in it
~/.deckhq/state.json Your acknowledgements, bench states, names and settings. Set DECKHQ_STATE_DIR to move it. It is deliberately not stored beside the package: npx owns that directory and may replace it on any version bump, which would throw your queue away silently.
~/.deckhq/cache/ Parsed session summaries, so a restart does not re-read every transcript on disk. Derived and disposable; delete it any time and it rebuilds.
~/.deckhq/ledger/ One JSON object per line, per day, behind deckhq stats. It holds no paths and no project names — a project is a hash — and it is pruned at ledgerRetentionDays, 90 by default.
~/.deckhq/backups/ A copy of your Claude Code settings file, taken before DeckHQ ever modifies it.
~/.deckhq/daemon.json The port a running daemon bound, so a hook can find it. Removed on a clean shutdown; nothing you own is in it.
~/.claude/settings.json Only with your explicit consent, and only a tagged hook block.

If a write ever fails, DeckHQ says so in the header rather than losing your acknowledgements quietly.

What hooks are for

Without hooks, DeckHQ infers state from transcripts. It can tell you a session is alive and whether the last word was yours or the agent’s. It cannot tell needs_input from stalled — a transcript alone does not distinguish those two states, and the header says so plainly rather than showing you a confidently wrong picture.

With hooks installed, state is exact and instant: a permission prompt raises a hand within milliseconds of it appearing in your terminal, and a thought bubble above the head says what tool the agent is running right now.

Consent, and taking it back

  • The consent screen shows you the literal JSON that will be written and the exact file it goes in. Nothing is written until you click.
  • Your settings file is copied to ~/.deckhq/backups/ before the first write.
  • Every entry DeckHQ writes is tagged, and removal deletes only tagged entries. A hook you configured yourself is reported and left exactly where it is.
  • Hooks are reported by delivery, not just installation. A hook aimed at a port nothing is listening on leaves a settings file that looks perfect while every event goes nowhere, so deckhq doctor counts the events that actually arrived and when the last one did.
  • Installing the Claude Code plugin instead writes nothing into your settings file at all, and uninstalling the plugin takes the hooks with it.

What a hook event may touch

A tool event moves a thought bubble and nothing else. Nothing about it touches ackState, the needs-you count, or the stall clock — there is a named INVARIANT: test for exactly that. A path outside the session’s own working directory is reduced to its file name, so a screenshot of your floor cannot carry someone else’s directory tree, and every payload string is flattened to one line of printable text before it is drawn.

What you can share, and what stays

deckhq doctor --share prints the report as a fenced block with everything that belongs to you taken out: no paths, no project names, no machine name, no hook port, no free-text error message, and a date to the day rather than the hour. Project names cannot leak by construction — the report counts distinct working directories and never keeps the strings — and a redaction pass runs over the assembled block anyway, because a runtime’s version string is text this project did not write.

deckhq ledger export --signed writes one day out with an Ed25519 signature so somebody else can check it has not been altered. The signing key is generated on your machine and never leaves it.
