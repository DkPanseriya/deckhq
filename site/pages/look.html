Two halves, and the difference between them is the point of this page. The first half is what the renderer draws today, photographed by the visual-regression gate. The second half is a designer’s drawings of a package that has not been built. Every image in it says so in its own caption.

A mockup is never a screenshot here. An image labelled design illustration was drawn against a specification; no build has produced it and nothing you install will look exactly like it. The rule is docs/MEDIA.md, and the site build fails rather than publish one of them unlabelled.

What ships today: three themes

All three are free and none of them is gated. A theme repaints materials and neutrals; the six state colours never move, so a raised hand is the same amber in all three and every theme is measured against the same contrast floors before it can be selected.

One populated floor per theme is a committed golden, which is what proves a theme reaches the bake rather than quietly not applying. These three are those goldens.

The interior, as it was designed

The floor was lit and furnished before anybody had designed the interior. WP-85 fixed that: one key light, a furniture set drawn rather than blocked out, four planting kinds told apart by shape, a reception with a threshold, and something on every desk.

The board below is the material palette that work was designed against — grounds, woods, fabrics and metals, each with the contrast it has to hold. The mockup beside it is the drawing the package was reviewed from, not a photograph of the result.

What shipped is the three goldens above. Compare them against the drawing: that comparison is the honest version of a before-and-after, and it is why both are on this page.

Coming in WP-88: the graphics control centre

The owner, 15 September 2026, asked for designer-curated interior options that mix and match — floor, carpet, colours, rugs, tables, chairs, sofa, plants — plus agent size, with the furniture scaling automatically.

None of this is built. It is WP-88a, b and c in the plan, and the three drawings below are what those packages are designed against. Today there are three themes and one agent size.

What is already fixed about it: every curated combination has to pass the same contrast, material and figure-halo gates the shipped themes pass, and changing agent size must change no plan geometry — the same population produces the same room rectangles at every setting.

Packs

Extra themes and avatar sets arrive as a single signed file. deckhq pack install <file> copies it into ~/.deckhq/packs/ and a running DeckHQ picks it up within a second. A pack carries colours and names and nothing else: there is no key in its format for a tier, a licence, an expiry or a feature flag, and a test runs the whole API surface with and without one installed and diffs the responses.

Every theme in a pack goes through the same contrast gates as a theme DeckHQ ships, and every avatar colour is held a fixed distance from every state colour, so an agent can never wear a state. There is no account and no network call anywhere in it.
