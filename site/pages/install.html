Install

Node 18 or newer, and nothing else. There is no build step, no runtime dependency and no account, whichever route you take.

npx

The one to start with. It downloads the package, runs it, and leaves no binary behind.

npx deckhq

That starts the daemon on 127.0.0.1 and opens the floor in your browser. npx deckhq doctor prints the environment report without starting anything, and npx deckhq --no-open starts the daemon without a tab.

A global install

Two features want deckhq on your PATH: the status line, and the plugin’s ability to start a daemon for you. npx leaves no binary, so those want a real install. 

npm install -g deckhq

Homebrew, winget and scoop

The release job renders a Homebrew formula, a three-file winget manifest and a scoop manifest against the sha256 of the tarball the npm registry actually serves, and attaches them to the GitHub Release along with a Windows zip. They install Node as a dependency rather than bundling it, and what they install is byte-for-byte what npx deckhq runs.

On the next release. That job exists and is tested, but it has never been run by a real tag, so no release page carries those files yet. There is also no Homebrew tap and no scoop bucket: today the manifests are files you point the tool at, not names you can type. packaging/README.md in the repository says exactly what to do with each one.

As a Claude Code plugin

The setup can happen inside the tool you already have open. In any Claude Code session:

/plugin marketplace add DkPanseriya/deckhq
/plugin install deckhq@deckhq

or from a shell, or against a checkout on disk:

claude plugin marketplace add DkPanseriya/deckhq
claude plugin install deckhq@deckhq
claude plugin marketplace add ./deckhq

That is the whole setup. The plugin brings:

  • The hooks, all of them, without touching your settings.json at all — installing the plugin is the consent, and uninstalling takes them with it.
  • The daemon, started on your first session. An async SessionStart hook checks whether one is already running and starts one if not, detached and without opening a browser. Ten terminals opened at once start exactly one daemon between them.
  • /deckhq:deck — opens the floor, starting DeckHQ first if it has to.
  • /deckhq:waiting — prints the queue: who is waiting, on what project, for how long.
  • deckhq_waiting, an MCP tool, so you can ask Claude itself what is waiting on you across every project. It is read-only: it can report the queue and cannot discharge it.

The plugin’s hooks carry no port. The daemon publishes the one it bound to ~/.deckhq/daemon.json and the hook command looks it up on each event, so a daemon that moved to another port keeps receiving everything.

If you had already installed the hooks from the floor’s header, remove them there after installing the plugin. Both routes work, but together they deliver every event twice. To remove the plugin: claude plugin uninstall deckhq. It takes out only what it put in.

In VS Code

The extension is the thin part: it finds the daemon on 127.0.0.1:4317–4326, starts one if there is none, opens the floor in a panel beside your code, and puts ▣ 3 waiting · 1 hand up in the status bar. It reads and posts nothing — a status bar cannot discharge a debt by displaying it.

Not on the Marketplace yet. Publishing needs a Marketplace publisher account and a token, and that has not happened. Until it does, build it from the repository: npx --yes @vscode/vsce package in vscode/, then install the resulting .vsix from the Extensions view.

The status line

Claude Code renders a user-configurable status line in every session, and DeckHQ can write one segment of it. Every terminal you have open becomes a live badge for the queue. 

deckhq statusline --install        # prints the exact JSON and the file. Writes nothing.
deckhq statusline --install --yes  # writes it
deckhq statusline --remove --yes   # takes it out again

Same discipline as the hooks: you see the literal JSON and the path before anything is written, your settings file is copied to ~/.deckhq/backups/ first, the entry is tagged, and removal deletes only the entry DeckHQ wrote. A status line you configured yourself is reported and left where it is. It needs deckhq on your PATH.

Uninstalling

  • npx: nothing to undo — it left nothing behind.
  • npm uninstall -g deckhq for a global install.
  • Hooks and the status line have their own removal, which deletes only the tagged entries DeckHQ wrote: the hooks screen in the floor’s header, or deckhq statusline --remove --yes.
  • Your queue, names and settings live in ~/.deckhq/. Delete the directory and there is nothing left of DeckHQ on the machine.
